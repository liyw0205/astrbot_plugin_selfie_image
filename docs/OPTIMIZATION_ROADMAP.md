# Selfie Image 三向优化方案（前端 / 后端 / 指令）

> 基线：`astrbot_plugin_selfie_image` 1.1.0  
> 主参考：`Railgun19457/astrbot_plugin_image_generation`（通用生图）  
> 辅参考：电报搬运工内嵌 Dashboard（bridge / 免 Web Token）  
> 原则：**借参考仓的工程能力，不照搬产品定位**。Selfie 的差异化是「AI 自拍人设 + 合影/看看腿等角色化指令 + 独立/内嵌 Web」。

---

## 0. 定位与边界（防误理解）

### 0.1 我们是什么 / 不是什么

| 是 | 不是 |
|----|------|
| AstrBot 插件：命令 + LLM 工具 + Web/内嵌页 | 独立 Bot / 独立前端工程 |
| 角色化自拍与合影能力 | 纯通用多供应商生图中台（那是参考仓强项） |
| 渠道管理、测试、监控、形象设置 | 把真实 key/token 写进仓库 |
| 单因失败提示、可操作文案 | 多可能兜底、开发腔报错 |

### 0.2 固定不变量（后续优化不得破坏）

1. AstrBot 原生配置只保留 `web.enable/host/port/token`；完整配置在 `plugin_data/.../selfie_image_config.json`。
2. 不引入 npm/Vite/React 作为默认前端链（除非单独立项）。
3. 不提交运行态：配置、缓存图、生成记录、形象图、真实密钥。
4. 内嵌 Dashboard：走 AstrBot 登录态 + bridge，**不要求 Web Token**；独立 Flask 仍可 Token。
5. 渠道 `proxy` 显式配置；生图 `ClientSession(trust_env=False)`，避免环境代理误伤。
6. 失败提示**单因**、可操作；禁止「A、B 或 C」式多可能兜底。
7. 晒腿等角色玩法**保留产品风格**；只做触审/稳定性优化，不擅自删玩法。

### 0.3 参考仓可借 / 不借

| 可借 | 不借 / 慎借 |
|------|-------------|
| 适配器模块化、模型能力开关 | 把 Selfie 改成「纯通用生图」丢掉自拍主线 |
| 任务队列 / 取消 / 任务查询 | 把全部配置塞回 `_conf_schema` |
| `openai` / `openai_chat` 分流、流式 gpt-image | 无差别照搬全部供应商（按真实在用再移植） |
| 不可重试状态码/关键词 | 把错误做成多原因堆砌 |
| 插件页 `pages/dashboard` + register_web_api | 依赖允许 same-origin 的 iframe（AstrBot 无此权限） |
| 多 key 轮询、额度展示 | 默认打开详细错误把上游原文甩给用户 |

## 2. 三向优化方向

### A. 前端（独立 Flask + 内嵌 Dashboard）

**目标**：管理员「一眼能配、一键能测、失败能懂、结果能刷」。

| 优先级 | 项 | 做法 | 验收 |
|--------|----|------|------|
| P0 | 内嵌免 token 稳定 | bridge 预加载、safeStorage、路径与电报一致 | 内嵌页无登录墙；按钮可点 |
| P0 | 渠道测试结果闭环 | 任务终态刷新、轮询失败重试、监控必有记录 | NewAPI 成功 ⇒ 页有图+监控有行 |
| P0 | 单因错误展示 | `error` 字段唯一原因；attempts 折叠 | 无多可能兜底 |
| P1 | 配置预检 UI | 保存/测试前标红缺 name/url/key/enabled_models | 未保存草稿不静默失败 |
| P1 | 模型列表：缓存 vs 已启用 | 下拉区分；未启用不可测或明确提示 | 无「有模型但测不到」误解 |
| P1 | 测试默认稳健参数 | 增强默认关、比例默认 1:1、关自拍参考 | 连通性测试不被增强拖死 |
| P2 | 渠道诊断卡 | 一键 `/v1/models` + 首选模型 dry-run 摘要 | 网络/401/空列表可区分 |
| P2 | 监控筛选与分页 | 已有基础上：来源/成功失败/模型过滤 | 大数据不卡 |
| P2 | 移动端/窄屏 | 表格与 modal 可滚 | 不挡操作 |

**前端禁区**

- 裸 `localStorage`（iframe 无 same-origin 会整页挂死）。
- bridge endpoint 收成 `page/api/...`（父页只认剥掉 `/api/` 后的相对路径）。
- 把独立 Flask 的 Token 逻辑硬套到内嵌页。

### B. 后端（Provider / 任务 / 配置 / 安全）

**目标**：「上游成功 ⇒ 插件必收尾；失败可诊断；配置难配错」。

| 优先级 | 项 | 做法 | 验收 |
|--------|----|------|------|
| P0 | OpenAI 图响应快路径 | `data[].b64_json` 直解，大 base64 不跑 HTML 扫描 | 1.7MB b64 秒级收尾 |
| P0 | trust_env=False + 显式 proxy | 生图/审核会话不继承环境代理 | pie-xian 类站靠渠道 proxy |
| P0 | 协议锁定 | 中转渠道默认不按模型名跳到 gemini 原生协议 | NewAPI 全 openai 可用 |
| P0 | 任务状态机 | queued→running→succeeded/failed 必写；异常也 failed | 无永久 running |
| P1 | 配置预检（目标 03） | 保存/测试共用；字段级错误脱敏 | 无 key 泄露 |
| P1 | 不可重试错误词典 | 401/403/404/model_not_found/unsafe 不空转重试 | 省额度、快失败 |
| P1 | openai vs openai_chat | 明确分流（可保留 gemini_openai 别名） | chat 出图模型可配 |
| P1 | 缓存回收一致性（目标 04） | 引用未断不删 | 监控图不丢 |
| P2 | 多 key 轮询 | 渠道 api_keys 列表 | 单 key 限流可切 |
| P2 | 流式 gpt-image（可选） | 参考仓 SSE；默认仍非流式 | 仅对需要站开启 |
| P2 | 插件公共 API | 提交/查任务/取路径 | 他插件可复用 |
| P2 | 按需移植 adapter | siliconflow/custom_http/modelscope… | 有真实渠道再合 |

**后端禁区**

- 密钥进 git / 日志明文。
- `CAST` 大整数、错误用 INTEGER 存超大数（本项目无 DB 主路径，但经济类记忆勿混入）。
- 把「上游成功」当成「插件成功」而不落盘/不改 task。

### C. 指令（命令 / 文案 / LLM 工具）

**目标**：「用户好记、好用；角色玩法在；风控不误伤风格」。

| 优先级 | 项 | 做法 | 验收 |
|--------|----|------|------|
| P0 | 帮助与别名一致 | `/生图帮助` 覆盖画/自拍/合影/形象/预设 | 用户不靠猜 |
| P0 | 合影增强 | 非人物参考**按风格拟人**，禁止当背景贴图 | 风景图合影出人 |
| P0 | 晒腿等玩法 | **保留**特写/晒腿模式；仅轻量降敏 | 风格不砍 |
| P1 | 会话模型切换 | `/生图模型` 或 `/画模型` 列表与切换 | 不全靠 Web |
| P1 | 任务查询/取消 | `/生图任务` `/生图取消`（会话维度） | 长任务可管 |
| P1 | 失败用户文案 | 单因、口语化、不提工具/审核堆砌（可配置详细错误给管理） | 群聊体验稳 |
| P1 | LLM 工具参数 | 按模型能力隐藏不支持项 | 少无效调用 |
| P2 | 预设/人设分块提示 | 参考仓 `[人物设定][预设][附加]` | 多来源不打架 |
| P2 | 进度提示模板 | 可配置占位符 | 运营可调 |

**指令禁区**

- 擅自删除「看看腿/合影」等产品指令。
- 帮助写开发腔（软顶、L 层、预算公式）。
- 把 Web 管理口令暴露给普通群用户。

### 3.3 每轮自动步骤（给后续 Agent / 自己）

```text

2. 取队列中第一个「进行中」或「待开始」

   - python -m py_compile 相关模块

7. 推送 origin
8. 目标文档标「已完成」，下一项改「进行中」
9. 开发文档目标表同步
```

### 3.4 版本策略

- 兼容修复 / 内嵌与收包：`1.1.x`
- 指令任务系统 / 协议大改：`1.2.0`
- 破坏性配置迁移：`2.0.0` + 迁移说明  
- `metadata.yaml` 的 `astrbot_version` 与真实依赖同步（当前 `>=4.13.0,<5`；若用新 Dashboard API 再抬下限）。

## 4. 自我审查清单（Bug / 漏洞 / 误理解）

每轮改动合并前必须过：

### 4.1 正确性

- [ ] 成功路径：上游 200 + 有图 ⇒ task succeeded + 监控有记录 + 前端可显示  
- [ ] 失败路径：必有单因 `error`；不会卡在 `running`  
- [ ] 配置：未保存草稿 vs 已保存；enabled vs cache 模型不混淆  
- [ ] 合影：非人物参考拟人，不把原图当背景  
- [ ] 晒腿：模式与风格仍在（若目标未要求删除）

### 4.2 安全

- [ ] 无真实 key/token/proxy 账号进仓库、进测试断言、进文档示例  
- [ ] 日志/records 脱敏（Authorization、api_key、token=）  
- [ ] Web：独立入口校验 Token；内嵌靠 Dashboard 登录  
- [ ] 路径：缓存读写防 `..` 穿越  
- [ ] 上传参考图：大小上限、类型校验  

### 4.3 并发与资源

- [ ] 全局超时与渠道超时一致、可解释  
- [ ] 信号量/并发上限有效  
- [ ] 大 b64 不阻塞事件循环（快路径）  
- [ ] 临时文件/缓存有回收策略  

### 4.4 兼容

- [ ] 旧配置字段仍可读  
- [ ] 独立 Flask 与内嵌页双路径  
- [ ] AstrBot 版本约束正确  

### 4.5 常见误理解（显式否决）

| 误解 | 正确理解 |
|------|----------|
| NewAPI 日志成功 = 网页一定有图 | 还须插件收包、落盘、task 终态、前端轮询 |
| 优先级为空 = 测不了 | 空优先级回退全部已启用模型；测试靠选中渠道+模型 |
| 刷新到 models_cache = 已启用 | 必须进 enabled_models 并保存 |
| 环境有 HTTP_PROXY = 插件一定走代理 | 现 trust_env=False，要靠渠道 proxy |
| 内嵌还要 Web Token | 内嵌应免 Token；若出现登录墙多半是 bridge/storage 挂了 |
| 优化提示词 = 删除晒腿 | 优化触审与稳定性，玩法默认保留 |
| 参考仓有的都要搬 | 按真实渠道与 ROI 移植 |

## 8. 成功标准（方案级）

1. 任意维护者只读 `OPTIMIZATION_ROADMAP` + 当前 target 即可开工，无需口头对齐。  
2. 每完成一项都有：代码 + 验证证据 + commit + push + 目标状态更新。  
3. 前端/后端/指令三条线都有可勾选验收，且互不吞并产品差异化（自拍）。  
4. 审查清单能拦下：永久 running、密钥泄露、内嵌登录假死、合影当背景、误删晒腿。
