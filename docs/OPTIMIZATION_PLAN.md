# Selfie Image 优化方案

## 1. 现状结论

本方案基于当前工作区代码、测试和构建检查整理，目标是为后续迭代提供可执行的优先级和验收标准。当前版本的功能完整度已经较高，优化重点应放在稳定性、性能、可维护性和发布质量，不建议继续无边界增加入口或重写现有提示词系统。

最新完整发布验证基线（2026-11-15，1.7.29）：

- 全量 pytest `3584 passed, 702 subtests passed`，耗时 385.53 秒；完整发布门禁通过 compileall、无操作检查、Dashboard 构建/回退/Node、版本/JSON/制品与 `git diff --check`。
- Dashboard JavaScript 使用 Node 验证 15 个源脚本和 2 个生成脚本；60 个 Git 跟踪 JSON 文件解析与必填字段检查通过。
- 临时运行期 ZIP 检查：147 个文件，2,425,424 bytes；解压后 5,662,947 bytes；SHA-256 `f0723c9570c767f556abdbec1dba3a725c80573d816f7ecbc9f72921d243fa2e`。单文件 2 MiB、解压 12 MiB、ZIP 6 MiB 预算均满足；新增兼容 helper、Prompt、Cache、Health、Context、QQ group、Selfie profile、ImageChannel controller、ImageCommandService、SelfieWorkflowService 与 GenerationRuntimeService 均纳入运行期包。
- 本地验证使用 Python 3.13.13；Python 3.10～3.12 的 CI 矩阵及 Python 3.13 的远端结果需推送后确认。未进行目标宿主字体及真实投递验证。

主要结构性事实：

| 领域 | 当前情况 | 对后续迭代的影响 |
| --- | --- | --- |
| 主插件 | `main.py` 当前约 5204 行；快速试画、批量执行、自拍批量准备、状态报告、普通图片命令及自拍/合影/COS/腿部路径均已拆分，AstrBot 原入口保留薄代理 | 后续按任务服务边界继续拆分 |
| Web 层 | `webui/web.py` 约 1582 行，Dashboard API 约 1201 行；已共用主要业务 controller | Flask 与内嵌 Dashboard 需要持续保持契约一致 |
| 生成链路 | 已有公平调度器、模型/密钥回退、超时、渠道健康状态和取消清理 | 重点变成网络连接复用、回退策略可观测性和边界测试 |
| 持久化 | 生成记录已经使用 SQLite；任务快照仍是 JSON，状态变化时通过锁和延迟快照写入 | 记录查询可继续扩展索引；任务快照在高并发下有写放大风险 |

## 3. P0：先建立发布和安全底座

## 4. P1：降低网络和查询开销

### 4.1 建立按代理/渠道复用的 HTTP 会话池

当前 `generation/generator.py` 在没有外部 session 时会为一次模型尝试创建 `aiohttp.ClientSession`，`core/proxy.py` 对 SOCKS 代理也会创建独立 session；此前默认请求头还设置了 `Connection: close`。本轮已改为 `keep-alive`，并已引入受控的生命周期级 session registry。

建议在插件生命周期内维护一个受控的 session registry：

- key 由代理 ID、代理协议和必要的 TLS 参数组成；
- HTTP/HTTPS 复用连接，SOCKS 使用独立 connector；
- 空闲超时后回收，插件 `terminate()` 时统一关闭；
- 每次请求仍使用现有的总超时、读取超时和响应体上限；
- 已将默认请求头改为连接复用；只有明确不支持 keep-alive 的渠道才应保留关闭选项；
- 记录连接复用命中、创建、回收和失败原因。

先以开关形式灰度，保留按请求创建 session 的兼容路径。不要把同步 `_sync_try_model` 迁回事件循环；同步兼容路径必须继续隔离。

已落地：直连/HTTP 代理按身份复用，SOCKS 使用独立 connector；插件卸载统一关闭；保留按请求创建和同步兼容路径。

验收标准：批量 10 张、双渠道回退和 SOCKS 渠道的功能结果与现有测试一致；同一渠道连续请求的握手次数下降；取消、超时和插件卸载后无未关闭 session 或活动连接。

### 4.2 优化配置目标缓存

`core/models.py` 的目标缓存键会把完整 `raw` 配置序列化后再查缓存。当前配置规模尚可，但每次模型选择都可能重复遍历大量 COS/预设之外的配置字段，并产生深拷贝。

- 仅在配置变更时清空或替换缓存；
- 随机模式继续绕过稳定缓存；
- 保留当前“返回副本”的隔离语义。

验收标准：配置未变化时目标选择不再序列化完整配置；配置保存后旧渠道、优先级、代理和模型映射不会残留；现有 target cache 回归测试全部通过。

### 4.3 为记录查询增加物化字段和全文索引

`generation/record_database.py` 已经把分页和筛选下推到 SQLite。此前 `source`、`model`、`keyword` 主要通过 `json_extract` 和 `instr(text_lower(...))` 查询，保留记录增多后需要扫描大量 JSON；收藏/置顶记录又可能超出普通保留量，因此本次增加物化列与可选关键词索引。

### 4.3.1 长提示词、缓存和写入压力验证

本次先修复测量发现的运行期缺陷：`with sqlite3.Connection` 只处理事务，不关闭连接。现在初始化、读、写、裁剪和清空的全部内部连接均在提交或回滚后确定关闭；回归持有连接强引用，验证无需 GC 也已关闭，并验证写入异常回滚。基准没有常驻 anchor connection，包含实际连接开关及可能的最后连接 checkpoint 成本。
