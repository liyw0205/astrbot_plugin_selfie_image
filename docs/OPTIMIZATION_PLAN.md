# Selfie Image 优化方案

## 1. 现状结论

本方案基于当前工作区代码、测试和构建检查整理，目标是为后续迭代提供可执行的优先级和验收标准。当前版本的功能完整度已经较高，优化重点应放在稳定性、性能、可维护性和发布质量，不建议继续无边界增加入口或重写现有提示词系统。

本轮完整发布验证基线（2026-11-16，1.7.48）：

- 全量 pytest `3654 passed, 1 skipped, 702 subtests passed`，耗时 239.78 秒；Python、Dashboard 和静态发布层门禁均通过 compileall、无操作检查、Dashboard 构建/回退/Node、版本/JSON/制品与 `git diff --check`。
- Dashboard JavaScript 使用 Node 验证 15 个源脚本和 2 个生成脚本；64 个 Git 跟踪 JSON 文件解析与必填字段检查通过。
- 临时运行期 ZIP 检查：148 个文件，ZIP 2,451,736 字节、解压 5,785,060 字节；单文件 2 MiB、解压 12 MiB、ZIP 6 MiB 预算均满足；新拆分的命令任务服务及既有工作流、controller 模块均纳入运行期包。
- 本地验证使用 Python 3.13.13；Python 3.10～3.12 的 CI 矩阵及 Python 3.13 的远端结果需推送后确认。未进行目标宿主字体及真实投递验证；本轮 SIGKILL 仅为本机进程中断演练，不等同真实断电。

## 1.1 本轮已落地

本轮先完成 P0 中可独立验证的底座改动，未改变生成策略和记录契约：

- 统一图片几何限制：默认单边 16,384 像素、总像素 64 MP、动画最多 8 帧，并在 Dashboard 配置表单中可调整；校验只读取 Pillow 图片头，不展开像素。
- 统一接入自拍上传、辅助形象、事件引用图、画布上传和上游生成结果；超限请求在进入审核、图转文或缓存前终止。
- 生图、编辑、模型列表和结果下载请求默认使用 `Connection: keep-alive`，降低重复握手开销。
- 新增 `scripts/verify_release.py` 发布门禁，覆盖测试、编译、无操作检查、Dashboard 构建/回退一致性、JSON 解析和 `git diff --check`。
- 新增 `scripts/check_dashboard_javascript.py` 与 `.github/workflows/ci.yml`：发布门禁按 Python、Dashboard、静态层拆分；CI 覆盖 Python 3.10～3.13、Node.js 前端语法检查，以及无 Node 时的可选跳过路径。
- 参考图内容寻址缓存索引增加目录项快照和文件签名增量刷新：连续的新内容 miss 不再重复递归扫描目录，外部新增/删除、嵌套目录变化和签名未变化的文件替换仍会触发重新发现或哈希校验。256 个旧缓存文件、16 次 warm miss 的本机合成基准中位数由约 28.1 ms 降至 18.3 ms；该结果不外推为生产上界。
- 发布测试流程按职责去重：Python 3.12 跑一次完整 pytest，3.10/3.11/3.13 跑兼容性子集；Dashboard job 仅负责 Node/页面门禁，制品 job 使用 `build_release.py --skip-tests` 复用前置测试结果，但仍执行编译、无操作、Dashboard、版本、JSON、制品和 diff 检查。默认本地 `verify_release.py` 与 `build_release.py` 仍保留完整 pytest。
- 继续减少发布流水线重复：兼容性 Python job 通过 `--skip-static` 只运行兼容测试；制品 job 使用 `--layer package` 校验版本、JSON 和运行期清单，最终 ZIP 仅由构建器往返校验一次。
- COS 目录匹配索引按内容签名惰性缓存，避免每次匹配重建约 770 套服装的术语和分词索引；记录收藏/置顶/标签更新在备注未变化时跳过 FTS 投影刷新。
- COS 多视角拼贴回归改为全量轻量兼容性检查加 5 套代表服装深检，特殊套装仍逐项验证，避免测试重复生成 770 份七格提示词。

完整发布验证结果统一记录在上方验证基线中。

本次继续落地 P0/P1：

本次继续完成的查询与快照优化：

- SQLite 增加可选 FTS5 trigram 索引；仅用全文索引筛选候选，再按原有子串规则确认匹配；短词、NUL、缺少 FTS5/trigram 的环境继续使用原查询。
- 记录总量改为“受保护记录数 + `MIN(keep_limit, 普通记录数)`”的计数式，避免仅为 COUNT 排序物化普通记录；新增受保护记录与有效 JSON 查询 partial index，过滤继续由原列和 JSON 表达式裁决。
- 旧库启动自动创建索引，插入、替换、备注更新、删除、裁剪和清空同步维护；运行期索引错误不阻断记录写入，标记失效后在重启时重建。
- 任务快照排除队列位置、运行秒数等易失字段的写入触发；字段值未变化时跳过无效更新；生命周期与终态仍立即保存。版本号、写入计数、耗时和脱敏失败原因已接入健康接口与 Dashboard 健康页。
- 本轮补充累计写入字节、定时/强制刷盘、合并更新、跳过写入、写入失败率和写入耗时 P50/P95/max；快照 JSON 的 UTF-8 `size_bytes` 与实际保存字节一致。重复记录关联在无状态变化时跳过写入，并以 12 个并发终态任务验证每次终态都可立即重载。
- 启动恢复造成的快照重写也计入版本与写入次数；磁盘记录当前写入时间，当前耗时在内存即时更新、下一次写入时落盘。
- 新增可重复运行的 `scripts/benchmark_record_database.py`，仅在临时目录中生成模拟记录，不读取真实记录。
- 修正 SQLite 连接生命周期：事务提交/回滚后立即关闭连接，避免依赖 GC 回收文件句柄和触发 WAL checkpoint。关键词按最多三个采样 trigram 的文档频率选择候选；宽候选直接走原标量查询，稀有候选保留 FTS + 完整子串确认。
- 补齐长提示词、尽力驱逐文件缓存和同实例/独立实例写入基准；索引改动前的 10 万条结果见 4.3.1，partial index 与 ID-only 总量复测见 4.3.2，宽提示词前缀优化复测见 4.3.3。热缓存合成场景中的常用查询与前缀内全量命中关键词已达标；任意后缀宽词仍使用精确回退，不将单一夹具外推为稳态保证。
- 记录保留集总量计数式在隔离 SQL 微基准中由 p50 约 33.9 ms 降至 8.7 ms；100k filler 合成库本轮 recent/favorite/model/keyword p95 为 127.9/141.1/158.4/43.6 ms，同关键词标量回退为 1103.0 ms。数据仅代表本机合成场景，不外推为冷缓存、并发写入或生产尾延迟保证。
- 认证限流的封禁期独立于失败计数窗口，避免跨窗口提前解除封禁；增加来源隔离与精确到期回归。

## 4. P1：降低网络和查询开销

### 4.1 建立按代理/渠道复用的 HTTP 会话池

当前 `generation/generator.py` 在没有外部 session 时会为一次模型尝试创建 `aiohttp.ClientSession`，`core/proxy.py` 对 SOCKS 代理也会创建独立 session；此前默认请求头还设置了 `Connection: close`。本轮已改为 `keep-alive`，并已引入受控的生命周期级 session registry。

建议在插件生命周期内维护一个受控的 session registry：

- key 由代理 ID、代理协议和必要的 TLS 参数组成；
- HTTP/HTTPS 复用连接，SOCKS 使用独立 connector；
- 空闲超时后回收，插件 `terminate()` 时统一关闭；
- 每次请求仍使用现有的总超时、读取超时和响应体上限；
- 已将默认请求头改为连接复用；只有明确不支持 keep-alive 的渠道才应保留关闭选项；
- 记录连接复用命中、创建、回收和失败原因。

先以开关形式灰度，保留按请求创建 session 的兼容路径。不要把同步 `_sync_try_model` 迁回事件循环；同步兼容路径必须继续隔离。

已落地：直连/HTTP 代理按身份复用，SOCKS 使用独立 connector；增加默认 15 分钟惰性空闲回收，回收前检查 connector 无活动连接；注册表记录命中、创建、回收、关闭、失败类别和按传输类型的活动数量；插件卸载统一关闭；保留按请求创建和同步兼容路径。健康接口和 Dashboard 只暴露脱敏统计。

本轮继续完成结果图片 URL 的下载代理边界：

- `BaseImageAdapter` 支持独立的结果下载 session；目标配置可通过 `extra.download_proxy` 指定与生图请求不同的代理。
- 生成代理和下载代理按规范化身份复用注册表 session；代理不同则隔离连接池，临时 SOCKS 下载 session 在单次生成结束后关闭。
- HTTP/HTTPS 代理仍使用 aiohttp request-level `proxy`；SOCKS5/SOCKS5H 仅使用 session connector，避免把 SOCKS 握手误发给 HTTP 目标。
- 结果下载异常只保留脱敏的主机/路径标签和异常类型，不记录签名查询参数、完整 URL 或代理凭据。

本轮验收：本机 aiohttp 回环服务的连续两次请求只建立一个客户端连接；idle 回收、显式关闭、失败分类和健康接口已有回归。HTTP 代理、SOCKS、TLS、双渠道回退、取消/超时和目标宿主真实握手仍需独立夹具或目标环境验证，不能由回环测试外推。

结果下载代理验收：独立 HTTP 下载 session、生成 SOCKS/下载 HTTP 隔离、临时 SOCKS session 关闭、SOCKS connector 真实本机回环下载和敏感诊断回归均已覆盖。HTTPS proxy 的 TLS-in-TLS 行为、跨网络目标的真实握手、双渠道回退及取消/超时组合仍需独立夹具或目标宿主验证，不能由本机回环测试外推。

验收标准：批量 10 张、双渠道回退和 SOCKS 渠道的功能结果与现有测试一致；同一渠道连续请求的握手次数下降；取消、超时和插件卸载后无未关闭 session 或活动连接。

### 4.3 为记录查询增加物化字段和全文索引

### 4.3.1 长提示词、缓存和写入压力验证

本次先修复测量发现的运行期缺陷：`with sqlite3.Connection` 只处理事务，不关闭连接。现在初始化、读、写、裁剪和清空的全部内部连接均在提交或回滚后确定关闭；回归持有连接强引用，验证无需 GC 也已关闭，并验证写入异常回滚。基准没有常驻 anchor connection，包含实际连接开关及可能的最后连接 checkpoint 成本。

长短语直接 MATCH 在重复文本上会合并大量位置列表。本次改为采样首、中、尾最多三个不同 trigram，通过 `fts5vocab` 选择文档频率最低的一项；候选超过 `max(8, 保留记录数 * 10%)` 时直接执行原标量查询。这个阈值只用于成本估计，不限制结果数量。词频查询异常时回退到有界 trigram AND；FTS 查询失败仍回退标量并标记重建。最终 `instr(text_lower(...))` 保持权威，兼容大小写、Unicode、标点和空白，短词及 NUL 继续走标量。

python scripts/benchmark_record_database.py --records 100000 --samples 10 --prompt-chars 2048 --cold-cache-samples 3 --concurrent-samples 10 --compare-phrase

#### 4.3.6 短词精确扫描复测

trigram 无法为 1～2 字符或包含 NUL 的关键词生成候选。短词现在复用同一份 `generation_records_fts.search_text` 物化投影，仅执行 `instr(search_text, ?)` 精确确认，不再回退到逐行解析主表 JSON；FTS 表异常仍关闭该路径并回到原标量谓词。新增回归验证跨提示词/来源字段、结果元数据和 FTS 禁用后的等价结果。

在 10k `bundled-assets` 仓库资产派生语料热查询中，关键词“自然”匹配 2,863 条记录，p50/p95 从标量路径约 `180.5/180.6 ms` 降至约 `38.4/38.6 ms`。该数据仍是合成语料和热缓存证据，不代表用户生产分布；冷缓存、并发写入和目标宿主环境仍需单独测量。

#### 4.3.7 普通筛选窗口计数

普通列表筛选此前先执行一次 `COUNT(*)`，再执行一次排序分页；最近、收藏和模型筛选会重复扫描同一保留集。现在所有筛选形状都在分页 CTE 中携带 `COUNT(*) OVER()`，有结果时由首行提供精确 `filtered` 数量；offset 超出结果范围时才回退到原精确计数查询。关键词的 FTS/标量候选、损坏 JSON 过滤、排序和 `total` 保留集口径均未改变。

新增回归确认普通筛选使用窗口计数、空页仍返回完整数量，并保留普通/关键词结果契约一致。10k `bundled-assets` 热缓存基准（5 次样本，页面 30 条）中，最近、收藏、模型分页 p95 分别为 `14.2/11.5/12.7 ms`；短词精确扫描 p95 为 `38.6 ms`。这是本机合成热缓存数据，不代表冷缓存、并发写入或目标宿主的稳定上界。

#### 4.3.8 保留集总量计数式复测

旧实现通过 `retained_ids` CTE 对普通记录按时间排序后再 `COUNT(*)`；新实现利用受保护集与普通集互斥，直接计算 `protected_count + MIN(keep_limit, normal_count)`。在同一 100k 模拟库的隔离 SQL 微基准中，p50 约由 `33.9 ms` 降至 `8.7 ms`（约 3.9 倍）；边界回归覆盖 `keep_limit=1`、全保护、无普通记录、空库、分页偏移和损坏 payload。完整查询基准仍受 JSON 解码、筛选和排序影响，不能把该微基准直接等同于接口端到端延迟。

### 4.4 任务快照暂不立即换库，先降低写放大

`tasks/task_manager.py` 已有延迟快照和生命周期边界强制刷盘，当前设计对小规模部署是合理的。当前已补齐以下三项：

## 10. 不建议当前做的事情

- 不建议把插件拆成微服务；当前瓶颈主要在上游生成和插件内状态一致性，拆服务会增加部署和回执复杂度。
- 不建议立刻把 SQLite 换成外部数据库；先验证物化字段和 FTS5 是否足够。
- 不建议重写前端框架；当前 Dashboard 已有源文件组装和 fallback 校验，先治理契约和重复 controller。
- 不建议把所有提示词池合并成一个通用 DSL；现有 COS、腿部、自拍和 NAI 合同有不同约束，合并会提高回归风险。
- 不建议为了追求更高并发取消现有公平调度、取消等待和记录提交等待；这些行为是任务可靠性的基础。
