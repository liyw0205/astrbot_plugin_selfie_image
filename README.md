# Selfie Image 生图自拍

AstrBot 的生图、图生图、AI 自拍、合影与管理面板插件。

- 插件名：`astrbot_plugin_selfie_image`
- 当前稳定版：`1.8.14`
- AstrBot：`>=4.13.0,<5`
- 仓库：<https://github.com/liyw0205/astrbot_plugin_selfie_image>

## 功能概览

- 文生图、图生图，以及多张批量生成
- 固定形象自拍、换装、摆姿势、他拍、合影和多人同框
- 内置提示词预设分组：`特殊预设`、`动作预设`、`上身预设`、`下身预设`
- 多渠道、多模型、模型优先级、失败回退和任务队列
- 资产库、生成记录、收藏/置顶/标签、历史提示词、重试和画布编排
- 独立 Flask Web 面板与 AstrBot 内嵌 Dashboard
- 图片缓存、SQLite 生成索引、发送状态和缓存清理预览
- 自定义衣橱与今日日程联动，普通自拍每天使用一套衣橱服装
- 备份管理：按数据项备份/下载/恢复/删除，支持衣橱导入导出；完整备份恢复和上传恢复在重启插件后生效
- 可选提示词审核、出图审核、图片转文字和中英文提示词转换

## 安装

将插件目录放入 AstrBot 的插件目录，目录名建议保持为：

```text
astrbot_plugin_selfie_image
```

在插件目录安装依赖：

```bash
pip install -r requirements.txt
```

依赖包括 `aiohttp`、`Brotli`、`aiohttp-socks`、`requests[socks]`、`Pillow`、`Flask` 和 `Werkzeug`。

重载或重启 AstrBot 后，插件会加载内置预设并创建插件数据目录。

## 管理面板

### AstrBot 内嵌 Dashboard（推荐）

打开 AstrBot WebUI → 插件 → `Selfie Image 生图自拍` → `dashboard`。

内嵌页跟随 AstrBot 登录态，不需要再次填写插件 Web Token。适合已经运行 AstrBot 面板的部署。

### 独立 Web 面板

插件启动配置只保留 Web 入口：

```yaml
web:
  enable: true
  host: 127.0.0.1
  port: 14514
  token: changeme
```

默认地址：`http://127.0.0.1:14514`。如果需要从其他机器访问，将 `host` 改为实际监听地址，并设置自己的 Token。

`changeme` 仅是占位值；插件启动时会替换为随机 Token 并写入日志。修改 `host`、`port` 或 `token` 后需要重载插件。

面板可以管理：

- 生图、审核渠道，以及模型列表和优先级
- 试画、批量任务、任务取消、重试和任务详情
- 形象图片池、文字人设池、形象类型（自动/真人/动漫）
- 图片预设、导入导出
- 生成记录和资产库：筛选、分页、收藏、置顶、标签、备注、导出/导入
- 画布：多参考图排序、图生图、模板和结果对比
- 缓存上限、缓存清理预览、权限、额度和审核策略

除 `web` 启动配置外，完整业务配置由面板保存到插件数据目录，不建议手工编辑。

### 备份与恢复

备份管理最多保存 5 个 ZIP 归档。核心配置为必选项，生成记录、图片缓存和引用媒体按需选择；归档最多包含 10000 个文件，解压后不超过 512 MiB，压缩后不超过 128 MiB。生成记录使用 SQLite 在线快照，包含 WAL 中已提交的数据；不同数据项分别读取，不提供跨 Store 的同一时点快照。

完整备份恢复和上传恢复会先校验归档并准备恢复，等待生成任务和数据写入结束后才能提交。准备成功后暂停新生图与备份写操作，请重启插件使恢复生效；关闭网页不会取消准备。启动恢复在持久化 Store 打开前执行，替换失败或进程中断时使用事务日志回滚，回滚失败会保留原数据和现场。衣橱 ZIP 导入仍立即生效。

点击「恢复」打开窗口，选择已有备份或本地 ZIP，并勾选恢复内容；再次确认后自动上传、校验和准备恢复。恢复时核心配置也可不勾选，未勾选的数据保持不变；本地 ZIP 中没有的数据项会跳过。删除备份也需要二次确认。

备份上传和衣橱 ZIP 导入按 1 MiB 分块传输，上传期间可取消；逐块校验并核对完整归档后才提交。最多同时保留 2 个临时传输，总预算 256 MiB；15 分钟无活动或超过 1 小时后自动清理，插件卸载和重启也会清理未完成传输。

独立 Web 使用 Flask 文件下载，内嵌 Dashboard 优先通过宿主下载文件，旧版桥接缺少下载方法时回退到分块下载。衣橱导出使用独立临时快照，不占用 5 个备份名额。旧 JSON 上传、导入、下载和衣橱导出接口仅支持不超过 16 MiB 的归档。浏览器下载仍需组装完整 Blob，其内存占用不属于服务端分块预算。

## QQ / 聊天指令

发送 `/生图帮助` 查看指令速查图，发送 `/生图help` 查看完整说明图；完整图不可用时会返回同内容的文字说明。

### 图片

| 指令 | 用途 |
| --- | --- |
| `/画`、`/生图` | 自动判断：有附图或引用图时图生图，否则文生图；不会自动带入形象图 |
| `/文生图` | 只按文字生成；附图不会作为输入，也不会使用形象图 |
| `/图生图` | 必须附图或引用图，按文字修改参考图 |
| `/nai` | 使用已启用的 NAI 模型，优先 NAI4，其次 NAI5；无需加入普通生图优先级 |
| `/nai5` | 只使用已启用的 NAI5 模型；没有则提示未启用 |
| `/自拍`、`/看看` | 使用当前形象自拍、换装或摆姿势 |
| `/今日日程` | 查看当天事件、穿搭变化和当前衣橱来源 |
| `/衣橱`、`/衣橱添加` | 查看衣橱或附图导入服装；可用 `/衣橱启用`、`/衣橱停用`、`/衣橱删除` 管理 |
| `/衣橱穿 编号`、`/衣橱轮换 顺序` | 指定今天穿哪套；轮换方式支持 `顺序` 或 `随机`，编号也可替换为衣橱 id |
| `/看看腿` | 成年人物的腿部穿搭近中景，上身、肩颈和头脸可自然入画，视觉重点仍在腿部；形象图使用专用短裙/短裤穿搭，保留用户请求图服装，袜装按套装兼容随机；支持指定服装、姿势、视角和全身照，全身或明确露脸时使用第三人称 |
| `/看看你` | 以他拍视角生成当前形象的日常照片 |
| `/看看COS` | 从内置 COS 池随机换装；未指定时随机使用他拍、第一视角或自拍视角，也可明确写 `他拍`、`第一视角` 或 `自拍` 固定视角；可指定角色/类别，也可使用 `-c` 和预设 |
| `/合影`、`/合照` | 当前形象与用户、@对象或参考图同框；形象来自当前选中的图片或文字人设，不会发送图片池的其他图片 |
| `/生图模型` | 查看或切换当前会话的生图模型；发送 `清除` 恢复默认 |
| `/生图状态 [1h\|24h\|7d\|30d] [页码]` | 查看成功率、耗时、错误和历史，默认最近 7 天；别名 `/生图记录状态` |
| `/生图任务`、`/生图取消` | 查看或取消图片任务，可跟任务号或列表编号 |
| `/查看提示词 [六位编号\|最近]` | 查询保存的最终实际提示词；支持引用图片，QQ 转码后用相似匹配兜底，不确定时返回候选 |
| `/查看生图提示词 [六位编号]` | 使用辅助功能中选择的识图模型反推图片；未选择时使用当前聊天 LLM。反推编号可取回已有结果，生图编号可指定缓存图进行反推 |
| `/生图重发` | 重发本会话“已生成但发送失败”且仍缓存的图片，可能包含多张，不重新生成 |
| `/记录复用 记录ID [修改要求]` | 从生成记录详情获取记录 ID，提交重新生成任务；别名 `/记录重生` |

每张生成图都有固定的六位字母数字编号，例如 `A7K3MP`，批量图片分别编号，重启后保持不变。提示词查询结果分两条消息发送：第一条是编号等信息，第二条仅含提示词正文，方便复制。原记录查询失败时不会自动反推；普通用户仅能查询本人当前会话的记录，管理员可按编号跨会话排查。管理面板的生成记录支持按编号搜索，详情可复制编号或排查信息。

对话人格读取 AstrBot 当前会话的生效设置。自拍的外貌身份可以在形象图池和文字形象人设池之间切换；形象图模式无图且未启用 logo 回退时，仍兼容使用框架人格描述。画布使用框架默认人格。

数量用 `-c 3` 指定，可放在提示词任意位置；旧写法 `/画 3 ...` 仍兼容。总张数和并发上限分别设置，超过并发上限的图片任务会排队。常用参数还包括 `--ar 1:1`、`--resolution 2K`，具体比例和分辨率的支持取决于模型。

引用文字消息后发送生图指令，可以将被引用文字作为提示词；自己填写的正文优先。普通生图、COS 等提取 @头像时，会过滤触发指令的用户和 bot 自己，保留其他被 @用户的头像；合影不做这两项过滤。附图、引用图仍按各指令规则使用。

`/看看COS 列表`、`/看看COS 全部`、`/看看COS 查看` 可以浏览池内标题。

```text
/画 一只白猫坐在窗边 --ar 1:1
/画 -c 3 夜晚街头的电影感人像
/图生图 把背景改成海边，并保留人物服装
/自拍 捧脸，看着镜头自然一点 --ar 3:4
/合影 和我一起在咖啡店拍一张
/nai [柔和色彩] 樱花树下的成年女性 -c 2
/nai5 [细腻厚涂] 城市夜景中的女骑士
```

NAI 画师串可在管理面板 → 预设管理 → COS 池旁的「NAI 画师串」中增删、编辑和导入导出，每页 30 个。发送 `/nai 画师` 查看名称；`/nai 画师名` 设置当前群/私聊的默认画师串，`/nai 默认` 恢复默认。`/nai` 和 `/nai5` 共用本会话的画师选择，也支持临时写 `[画师名] 提示词`。纯文生图时，NAI4 的中文描述由当前文本 LLM 转为英文标签，NAI5 保留原文；画师权重不参与翻译。

附图或引用图片时，两个指令使用「反推后重新生成」的伪图生图：优先读取原图的 PNG/EXIF 生成提示词；没有有效生成信息时，调用当前会话的 LLM 识图。用户可写 `/nai 换成蓝色连衣裙，站姿`，修改会替换冲突的原图标签，再拼入所选画师串和质量词。反推模板位于 `data/nai/reference.json`，不自动带入形象图。批量只反推、合并一次；反推失败会停止，不发送生图请求。该流程只向 NAI 发送最终文字，不传原图，不保证原图构图、人物或种子复现。普通截图或 QQ 压缩图通常没有生成信息，需要当前 LLM 支持识图。

### 形象管理

| 指令 | 用途 |
| --- | --- |
| `/形象设置` | 附带、引用图片或填写图片 URL，添加形象图并选中；也可写 `自动`、`真人`、`动漫` 设置形象类型 |
| `/形象设置 编号` | 按 1-10 的固定编号切换形象图 |
| `/形象移除 编号` | 移除指定形象图，其他形象图不改编号 |
| `/形象人设添加 名称 描述` | 添加文字形象人设，也支持 `名称=小玉 描述=固定外貌特征`；添加后需按编号选择 |
| `/形象人设设置 编号` | 选择文字形象人设 |
| `/形象人设移除 编号` | 移除指定文字形象人设 |
| `/形象查看` | 查看当前形象、形象类型和今日状态 |
| `/形象清除` | 只移除当前选中的形象图 |
| `/形象刷新` | 刷新今日穿搭与自拍设定 |

两个形象池各有 10 个固定编号，删除不会重排，新增优先补最小空位。旧主形象图自动迁入 1 号位。管理页的“使用形象人设池”开关决定使用哪一种池，按指令选中编号不会自动切换池模式，切换模式保留另一种池的内容。文字人设池内置“小玉”“祈枝枝o.o”“奶包菜”“燕子回来了”“蛋姐”，用于描述固定外貌，不固定服装或动作。移除当前选中项后，会选中该池剩余的最小编号。

形象图模式只自动使用当前选中的形象图，池内其他图片不会一起发送。文字人设模式使用当前选中的外貌描述，不自动携带形象图或 logo，服装和日程继续使用已有逻辑。

自定义衣橱服装由 `/今日日程` 统一选择和展示，不另建重复的衣橱日程。普通自拍没有本次附图时，会按“形象图 1 + 衣橱服装图 2”的顺序发送参考图；服装图只提供衣服、材质、颜色、版型、印花和配饰，不会覆盖人物身份、脸型、五官、发型或体态。日程中明确指定的居家服、睡衣等换装仍优先保留。衣橱图片存放在插件数据目录的独立 `wardrobe/` 下，不参与生成记录资产清理。

形象参考页支持多选普通服装图片，逐张追加到衣橱；留空名称时使用文件名，填写名称时为多张图片自动编号。上传失败后可只重试未完成图片；停止导入会等待当前图片处理结束，保留已导入的内容。衣橱 ZIP 导入仍用于恢复插件导出的衣橱包，会替换现有衣橱，与普通图片追加导入不同。

每日轮换可选随机或按导入顺序，旧衣橱默认继续随机。顺序模式在新的业务日生成日程时选下一套，跳过停用或损坏的图片，轮完从头继续；当天重复读取或重启不推进。“今天穿这套”和 `/衣橱穿 编号` 指定当天的主服装，本地刷新仍保留它；次日从上次自动选择的位置继续，不因手动选衣跳过中间的服装。切换轮换方式保留今天的服装，下次自动选衣时生效。

### 预设

```text
/预设                         # 查看预设列表
/预设 2                       # 查看第 2 页
/预设 查看 电影感              # 管理员查看预设详情
/预设添加 电影感:低饱和电影光，浅景深
/预设删除 电影感
```

图像转换预设需要参考图才有意义，例如 `/图生图 变猫娘` 或在面板试画中选择预设。内置转换预设包括：

`变真人`、`变动漫`、`变猫娘`、`变Q版`、`变像素`、`真人化`、`变COS`、`漫画封面`、`证件照`、`果冻化`。

特殊预设按动作、上身、下身分组显示。服装结构预设可直接写入生图或 COS 指令：`特殊预设`随机选择上下身开放结构，`动作预设`随机选择动作，`上身预设`仅随机上身结构，`下身预设`仅随机下身结构。

## LLM 工具

启用插件配置中的 LLM 工具后，聊天模型可以调用：

- `generate_image`：普通文生图/图生图
- `generate_selfie`：当前形象自拍、换装、合影和同框
- `retry_last_generation`：重试最近一次生成

工具路由规则：

1. 普通 `generate_image` 不会因为提示词提到机器人名称就切换为自拍。
2. 普通生图只使用消息中明确附带的参考图，或用户明确引用的上下文图片，不会静默带入主形象图。
3. `generate_selfie` 使用当前选中的形象图或文字人设；附带图片默认作为服装、姿势、场景或合影对象参考。
4. 用户明确说“自拍、合影、和我一起拍、穿这套、换这身”等关系词时，模型应优先调用 `generate_selfie`。

## 渠道与模型

在面板的“渠道”中添加并启用至少一个图像渠道。

常见图像协议：

- `openai`：OpenAI 兼容的 `/images/generations`
- `openai_chat`：只提供 `chat/completions` 的 GPT 生图中继
- `gemini`、`gemini_openai`
- `grok`、`agnes`
- `novelai`：NovelAI 官方原生请求体和 Bearer Token，支持图片、ZIP 和 JSON 图片响应，并兼容中继遗漏压缩头的 Brotli 响应。支持官方 API 根地址，也可填写完整生图地址（例如 `http://chami.yyqzx.com/image/chami`），完整地址原样使用，不自动追加 `/v1`。模型查询使用 `/models`；上游未提供列表时，按其文档手动添加模型名。OpenAI 兼容中继请使用 `openai` / `openai_chat` 渠道，NAI 模型仍按中继协议调用。
- `jimeng2api`、`z_image_gitee`
- `hunyuan`：自动识别 `hy-image*`、`hunyuan-image*`，默认 Base URL 为 `https://your-company.copilot.qq.com`

可配置：

- 多渠道和多模型
- 启用模型优先级
- 调用模式：`sequence`（按顺序）、`random`（随机）、`fixed`（固定首个）
- 全局超时、并发上限、失败回退和批量失败策略
- 每个模型是否先做图片转文字

API Key 会在面板中脱敏保存。不要把真实 Key 写入 README、提交到 Git 或放进前端代码。

“出图设置”中的“启用预览隐藏”位于“开启每日次数上限”上方，默认关闭。开启后，聊天出图和 `/生图重发` 会发送带模糊封面的 APNG，缓存、下载和记录复用仍使用原图；封装失败会保留为发送失败，供后续重发。QQ 是否在预览显示封面、查看原图显示清晰图取决于客户端和转码行为；支持 APNG 的查看器可能直接显示清晰图。

## 权限、额度与审核

面板的“权限与限制”可以配置：

- 可使用人员、黑名单、用户白名单和群白名单
- 全局可用名单启用且非空时，仅名单内用户可以生图；此时用户名单和群聊访问类型由全局名单覆盖
- 管理员可用 `/生图加黑 ID/@用户 [理由]`、`/生图加白 ID/@用户 [理由]` 管理用户名单，用 `/生图释放 ID/@用户` 同时移出黑白名单
- 每日生成次数和请求冷却
- 提示词屏蔽词
- 提示词审核、出图审核、OCR/图片转文字模型
- 中文提示词是否翻译为英文，以及翻译模型

白名单可以按配置不计入每日额度。具体限制以当前面板配置为准。

## 缓存与数据

新安装默认图片缓存上限为 **1000 张 / 2048 MB**，已有安装保留原配置，请求图和生成图共用缓存目录。缓存回收不是“超过数字立即删除全部超出部分”：

- 自动清理只回收较旧、未被生成记录引用的文件
- 生成记录、收藏、置顶或其他资产引用中的媒体会受到保护
- 清理预览显示的是当前可回收数量；显示 `0 张 / 0 MB` 可能表示超限文件仍被记录引用，并不代表统计失败
- 删除资产记录不会在仍有其他记录引用同一文件时删除共享缓存

默认数据位置（相对于 AstrBot 数据目录）：

```text
plugin_data/astrbot_plugin_selfie_image/
├── selfie_image_config.json     # 完整业务配置
├── image_cache/                  # 图片缓存
├── generation_records.sqlite3    # 生成记录索引
├── generation_tasks.json         # 任务持久化快照
├── usage_stats.json              # 每日额度统计
├── media_sources/                # 原始媒体来源 sidecar
├── image_presets.json            # 图像预设
├── image_persona.json            # 主形象元数据
├── image-persona/                # 形象图片池
├── cos_pools.json                # COS 随机池
└── studio_sessions.json          # 画布会话
```

旧版 `generation_records.json` 迁移到 SQLite 时会保留 `.bak` 备份。建议通过面板导出资产元数据，迁移或升级前同时备份整个插件数据目录。

## 任务、记录与发送状态

生成任务会记录来源、提示词摘要、参考图数量、模型尝试、排队进度、成功/失败状态和发送状态。任务中心保留活动任务以及最近 50 条终态任务；生成记录和资产库是更长的持久历史，删除任务元数据不会删除关联生成记录或缓存。

“生成成功”和“发送成功”是两个独立状态：

- 图片已经从上游取得并写入缓存，代表生成成功
- QQ/其他平台消息发送完成，才代表发送成功
- 图片已生成但发送失败时，记录仍保留，可使用 `/生图重发` 或面板中的重试/下载功能

资产库和生成记录使用服务端分页，并缓存相邻页的元数据；切换分页时仍会按权限和 Token 请求媒体内容。
